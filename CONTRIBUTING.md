# Contributing

Start with an issue describing the learner need, campus context, proposed change and how to verify it. Small corrections can go straight to a pull request. Work in a branch; maintainers review changes before merging. Be explicit about what you tested and what still needs review.

Software contributions use MIT. Educational content contributions use CC BY 4.0. By submitting, you confirm you can offer your contribution under the applicable license. List sources, permissions, dialect, audience, level and review status. Mark adaptations. Do not contribute student/family data, credentials, private Drive links, restricted religious content, or unattributed third-party text.

For Tibetan corrections, distinguish spelling, Wylie transliteration, local pronunciation, register and translation. Identify regional variation rather than presenting one phonetic form as universal. Qualified educators should record review scope and evidence without implying review of the full course. Attribution to a teacher or historical text needs a verifiable, appropriately licensed source.

For a content update, follow `docs/CONTENT.md`, regenerate the catalog and run the build check and tests from the README. UI changes should be checked at desktop and mobile widths and in print. Keep the default app usable offline and without dependencies. Do not add telemetry or server storage for personal notes.

Major features such as accounts, enrollment or LAN administration need a separate reviewed design covering real user need, privacy, permissions, rollback and maintenance. The roadmap is not authorization to operate a school or automate decisions about people.
